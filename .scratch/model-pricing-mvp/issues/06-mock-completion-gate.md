# 06: 完整 mock 验收与真实调用门禁

Status: ready-for-agent
Blocked by: 02, 03, 04, 05
task_id: model-pricing-mvp-20261019-06

**What to build:** 一次可恢复的 mock 验收证明全部纳入模型类型的数据和计费链路跑通，并产出可靠的阶段报告。报告未通过、缺项或已失效时，执行器拒绝真实调用，页面与消费数据不能显示为真实接入成功。

**Blocked by:** 02 — 文本与视觉 mock；03 — 图像 mock；04 — 嵌入 mock；05 — TTS 与 ASR mock。

- [ ] 基于已完成切片形成完整场景清单，覆盖文本、视觉、图像、嵌入、TTS、ASR 的配置→可信请求→预占→模拟响应→用量/折算→订单→企业余额→成员已用→流水→查询展示；视频不伪装已接入。
- [ ] 成功、幂等重放、调价中的订单、不足额、确定无消耗、未知消耗、超预占、事务失败回滚、跨租户/角色越权均有逐项断言；未执行、缺项和 skipped 不算通过。
- [ ] 不通过就持续停留 MOCK；没有真实厂商/真实存储流量，不消费三次真实额度，不因问题难以复现而削弱测试或把错误吞成成功。
- [ ] 报告由执行器生成，包含任务/运行标识、时间、代码与契约摘要、测试环境脱敏标识、逐模型场景、脱敏订单/流水证据、断言结果和汇总；能够恢复继续，不仅是一个可手填的 passed 标记。
- [ ] REAL 执行入口检查报告完整性、当前代码/契约/计费配置摘要及测试环境；缺报告、报告失败、摘要改变、环境不匹配或计次不能落盘时拒绝执行。禁止默认从 mock 自动切换到真实。
- [ ] 真实计次按供应商＋模型＋能力持久共享，发出请求前原子占用；最多三次、失败/SDK 重试/业务子调用计入；重启后不能归零。异步轮询单独有界记录。
- [ ] 汇总 API 七个目标操作、四个停用操作及历史查询/不可变保护的定向回归；验证 mock 模式标识、模拟无厂商费用及未知账务状态的展示，记录实际执行与未执行项。
- [ ] 只有完整 mock 门禁通过才允许 07–09 进入真实测试；后续代码变化必须刷新并重跑受影响 mock 场景，不能把本票完成当作永久放行。

**Evidence:** 聚合 AC01–AC08、AC11–AC13，验证 AC09 的计次机制但本票不发出真实调用。交付可复核 mock 报告及通过/失败结论；前台单独的接入和计费状态与报告一致。
