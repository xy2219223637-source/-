# 09: TTS 与 ASR 真实接入及账务核对

Status: ready-for-agent
Blocked by: 06
task_id: model-pricing-mvp-20261019-09

**What to build:** mock 全流程通过后，分别使用当前配置的 TTS 与 ASR 最低有效请求，验证可用音频/识别结果、原始用量和折算 Token，完成企业及成员账务核对和真实消费展示。

**Blocked by:** 06 — 完整 mock 验收与真实调用门禁。

- [ ] 根据实际配置、auto 路由及厂商官方协议确认 TTS 与 ASR 实际服务、资源和模型；未使用的环境变量模型名不能作为真实路由证据，最低字符/音频时长必须来自厂商有效规格。
- [ ] 真实协议或适配变化先更新并通过受影响 mock 场景、刷新报告；MOCK 失败或缺报告时不得发起真实提交、生成或收费探测。
- [ ] TTS 与 ASR 分别按供应商＋模型＋能力最多三次最低有效提交；失败和自动重试计入，次数持久共享且重启不归零；轮询独立计数并有明确时间/次数边界。
- [ ] 核验 TTS 音频可解码、ASR 识别结果及适用时间信息；保存能核对的字符/时长/真实 Token 证据，按该模型当前已确认规则计算，不能凭音频存在就推定 Token 或费用。
- [ ] REAL 订单保存开始时规则；企业扣额、成员已用和唯一流水及查询页面一致。未知用量或不确定超时进入待核对，不能无证明释放或重复调用；无厂商实际金额时显示未知。
- [ ] ASR 临时上传/存储、提交、轮询与清理均有同次运行的脱敏证据，清理失败可恢复，不触及无关资源或自动开启其他 worker。
- [ ] TTS 与 ASR 分别输出接入/计费两个结论及次数、最小参数、产物有效性和账务差额；两者任一失败不得以另一项通过代替。

**Evidence:** 对应 AC06–AC10、AC12–AC13；将所有实际已验证与未验证项目分开报告。缺厂商协议或未授权的环境副作用需明确记录，不能猜测执行。
