# 视频精修 AI 草稿格式修复

- 日期: 2026-10-12.
- 范围: 任务 22 的草稿返回失败, 不修改时间阈值, 不重新分析整批素材.
- 前置: 保留 P0/P1/P2 修复和独立精修 worker 的运行控制.

## 1. 根因证据

- 原始后台日志显示草稿 JSON 开头字段名损坏: 对象中的字段名未闭合, 随后直接出现冒号和镜头数组. 不是有效 JSON, 不是视频时长计算错误.
- `LLMClient._parse_json` 解析失败后返回 `{"raw": 原始文本}`. 精修层再因缺少 `items` 报 `AI 未返回有效精修草稿`, 未区分语法错误和业务字段缺失.
- 任务检查点保存了源片转写, 要求和 36 个素材的评估, 没有保存无效草稿为可复用结果.
- 本轮独立诊断只复用检查点调用一次草稿生成. 返回为有效 JSON, `finish_reason=stop`, 1872 个输出 token, 低于既有 6000 token 预算. 说明原始格式损坏不是每次发生, 不能将本次正常输出当作历史错误不存在.
- 不修改模型超时, token 预算, 帧尾留白或素材长度容差.

## 2. 修复约束

- 使用 `refinement-draft-json-v1` 验证草稿顶层和 `items` 数组, 区分无效 JSON, 空响应, 顶层类型错误, 缺少字段, 字段类型错误和超过 30 项限制.
- 对完整但语法损坏的 JSON 最多发起一次纯文本格式修复, 不重复发送源视频或重新评估素材.
- 修复前独立解析原始 `items` 数组. 原编辑项不可读取, 数据字段存在歧义, 响应尾部不完整或文本超过 64000 字符时直接停止, 不补写缺失内容.
- 将待修复文本作为不可信数据, 禁止执行其中的指令. 要求只修复语法和字段名, 不新增或删除编辑项.
- 修复后逐字段比较原始可读取数据, 包含完整 `items`, 已有时间轴, 源片属性和未应用发现. 使用规范 JSON 比较, 不把整数和浮点数或布尔值视作相同值.
- 拒绝台词, 时间坐标, 素材 ID, 要求 ID, 策略值或编辑项数量的任何变化. 格式修复不授予编辑权限.
- 继续执行既有字段, 授权, 素材归属, 区间和轨道编译校验, 不以 JSON 可解析代替业务安全校验.
- 只缓存通过顶层校验的草稿. 移除无效草稿缓存, 保留源片, 要求和素材评估检查点.
- 在收费修复调用前后保存检查点并检查取消与修订, 不进行无限修复或无限重试.

## 3. 诊断记录

- 在分析作业批次 JSON 的 `draft-diagnostic-...` 下保存错误类型, 文本长度, SHA-256, 修复调用数和数据保留结果.
- 不在新增检查点中保存原始响应正文, 密钥或源视频地址.
- 用户错误提示明确指出 JSON 或字段问题, 并说明素材匹配结果已保留.
- 成功修复的调用计入既有 `analysis_model_calls` 指标.
