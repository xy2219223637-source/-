# 视频精修优化方案

## 1. 文档定位

- 文档日期: 2026-10-12.
- 状态: 待实施设计, 不代表相关功能已经上线.
- 适用模块: 视频精修工作台, 素材评估, 自动配音, 时间轴编译和预览渲染.
- 核查代码基线: `afd8eef2a0755bb369512adf2e72f43c37857537`.
- 案例环境: 测试数据库 `enrui_ai_commerce_agent_test`, 任务 `21`.
- 实施原则: 保留现有用户改动和任务历史, 不直接修改线上任务, 不通过放松安全校验掩盖计算错误.

本文规定一个完整实施方案: 精准定位素材有效区间, 用统一时间基准匹配音画, 自动修正可处理的轻微差异, 仅将真实内容风险交给用户.

本文中的新增字段, 错误码, 配置名和模块名均为设计建议. 实施时必须同步调整后端校验, 前端类型, 哈希, 缓存和渲染协议, 不得当作现有接口直接调用.

## 2. 结论与目标

### 2.1 采用的最终方案

采用以下组合, 不采用全局提高误差阈值的单点修改:

1. 使用整数帧预算和音频样本数计算音画长度, 消除重复取整.
2. 在素材内部定位真正需要的内容, 不默认从候选片段开头截取.
3. 自动调整最后一个素材选段, 在有效内容范围内匹配配音.
4. 区分技术性帧尾留白与内容性展示停留, 为新增展示段设置有边界的留白策略.
5. 自动修正后重新编译与校验, 不能安全修正时才请求人工处理.
6. 保留完整台词, 同商品来源, 字幕可信时间, 授权修改范围等硬性约束.

### 2.2 用户侧目标

- 输入精修目标后, 能自动生成可播放预览, 不因系统生成的几十毫秒误差卡住.
- 只使用与当前目标有关的素材局部, 避开准备动作, 空镜和无关内容.
- 查看每个素材的实际使用区间, 选择理由和自动调整结果.
- 仅增加展示镜头时, 不默认增加台词或延长原片.
- 真正缺少素材或需求冲突时, 能理解原因并直接完成必要操作.

### 2.3 工程侧目标

- 保证选段, 编译, 校验和渲染使用相同的时间语义.
- 保证修正可追踪, 有界, 幂等, 不产生无限重试.
- 保证已有方案可读取, 已取消任务不自动恢复, 已接受版本不重写.
- 为内容质量和技术正确性分别建立验证标准.

## 3. 已核实的现状

### 3.1 现有能力

| 能力 | 当前实现 | 限制 |
| --- | --- | --- |
| 局部素材裁切 | 使用 `material_segments[].source_range` 保存起止时间 | 已支持裁切, 不是只能使用整个文件 |
| 同商品素材匹配 | 基于冻结快照和素材分析筛选 | 同商品关联不等于 SKU 或包装一定匹配 |
| 素材相关性评估 | 选择已有 `highlights` 区间并排序 | 缺少细分分析时, 候选可能覆盖整个素材 |
| 选段长度适配 | 根据目标长度截取候选区间 | 主要从候选起点截取, 缺少区间内部精确选点 |
| 真实画面核验 | 抽取选段开头, 中间和结尾画面 | 采样不等于完整连续观看 |
| 新增局部配音 | 先生成 TTS, 再按实测长度匹配素材 | 时长使用整数毫秒与浮点帧率重复转换 |
| 独立轨道编译 | 生成画面, 叙事音频, 字幕和源片到输出映射 | 轨道权威坐标仍主要为整数毫秒 |
| 预览渲染 | 按选段裁切, 校验规格和完整解码 | 编译与音频样本填充规则需要一致升级 |
| 用户要求解析 | 将要求与编辑项关联 | 不同阻塞容易被统一标为等待素材 |

### 3.2 任务 21 的失败证据

- 精修目标: 增加一个商品展示的镜头.
- 原片: `国光湿巾_成片_001.mp4`, 时长 `22780ms`, 帧率 `30fps`.
- 配音: 已生成成功, 实测 `9240ms`, 状态 `ready`.
- 帧对齐后的目标展示长度: `9267ms`.
- 实际选段合计: `9299ms`.
- 画面与配音差值: `59ms`.
- 当时校验容差: `33ms`, 约一帧.
- 两次分析均产生 `VOICEOVER_DURATION`, 后续连带产生 `REQUIREMENT_UNRESOLVED`.
- 未创建预览记录, 失败发生在预览入队之前.
- 任务随后变为 `CANCELLED`, 现有记录不能确定取消操作由谁触发.

| 素材 ID | 源素材起止时间 | 使用长度 |
| --- | --- | --- |
| `254` | `0ms - 2533ms` | `2533ms` |
| `254` | `2567ms - 5300ms` | `2733ms` |
| `205` | `0ms - 4033ms` | `4033ms` |

内存验证结果: 将最后一个选段结束时间改为 `4000ms`, 总长度变为 `9266ms`, 差值为 `26ms`, 原有两条阻塞均消失. 该验证没有修改数据库, 也没有执行真实预览渲染.

### 3.3 已定位的根因

- 配音长度先向上取整到帧边界.
- 每个素材片段再根据剩余整数毫秒计算结束点, 并向上取整.
- 片段端点分别转换为毫秒后, 差值与求和不再严格等于整数帧数.
- 最后一个选段可能多取一帧, 将原本合理的技术尾差扩大到校验范围之外.
- 要求解析将有关联阻塞的要求统一标记为 `AWAITING_MATERIAL`, 导致界面误导.
- 渲染器还会按音频样本数检查填充长度. 只放宽编译器阈值, 仍可能在渲染阶段被拦截.

### 3.4 素材内容选段的独立问题

- 现有裁切能力解决了文件长度问题, 没有完整解决内容定位问题.
- 已有分析区间过粗时, 不能保证截取起点就是商品最清楚的时刻.
- 当前相关性评估提示主要要求选择已有片段索引, 不在评估阶段生成更细的内容边界.
- 自动补足时长主要延续候选顺序, 不能只凭素材级相关性分数保证局部质量.
- 三帧核验可能漏掉中途的字幕, 镜头变化, 遮挡或商品切换.

## 4. 范围与不可违反的约束

### 4.1 本期实施范围

- 修复帧取整累计误差.
- 增加候选局部区间的定位与核验.
- 增加内容安全范围内的选段适配和自动修正.
- 建立新增展示段的有界尾部留白策略.
- 改善需求解析, 阻塞分类, 进度和素材使用信息.
- 增加测试, 指标, 灰度和历史任务处理流程.

### 4.2 本期不默认实施

- 声音克隆或复刻原声.
- 从混合音轨无损分离背景音乐.
- 自动去除硬字幕.
- 为补足时长循环素材, 定格画面或加入无关镜头.
- 默认加速或减速原片, 原配音或新增 TTS.
- 未经确认自动改写用户台词或增加产品功效声明.
- 对所有素材执行完整重分析.

视频轻微变速可以作为后续显式选择的能力, 不能作为本期自动兜底. 如后续实施, 仅允许已验证静音的商品展示画面, 必须同步调整渲染协议和来源映射.

### 4.3 硬性约束

- 不截断有效语音, 不通过缩短音频掩盖画面不足.
- 不越过已核验的素材有效区间来补足时长.
- 不跨企业使用素材, 不选择冻结快照外的文件.
- 不将同商品标签作为 SKU 和包装一致的唯一依据.
- 不把包装印刷文字当作叠加字幕, 也不把叠加字幕当作干净画面.
- 不将采样核验表述为完整连续观看或绝对无风险.
- 不修改无关源片区间, 不改变未授权的配音和总时长.
- 不在没有干净画面时直接覆盖矛盾的烧录字幕.
- 不发布已取消, 已被新修订取代或来源已失效的作业结果.

## 5. 用户意图与音频策略

### 5.1 先确定编辑语义

| 用户意图 | 默认编辑类型 | 配音策略 | 总时长策略 |
| --- | --- | --- | --- |
| 增加一个展示镜头, 未要求新增口播 | `VISUAL_REPLACE` | 保留原配音 | 保持时长 |
| 明确插入一段展示, 保留原内容 | `SEGMENT_INSERT` | 根据用户明确意图选择 TTS 或无讲话展示 | 增加时长 |
| 明确新增讲解或口播 | `SEGMENT_INSERT` | 生成新增局部 TTS | 先测配音, 再匹配画面 |
| 替换某句口播 | `VOICE_REPLACE` | 局部 TTS | 匹配授权区间, 不自动延长 |
| 精简表达 | 关联压缩编辑单元 | 局部 TTS | 完整新句必须短于旧内容 |

- 将用户原文, 页面明确选择和已回答的澄清作为授权依据.
- 不将后台自动生成的 `supplement_narration=tts` 视为用户明确要求新增配音.
- 若用户明确使用插入语义且同时要求保持完整原内容与固定总时长, 先检查冲突.
- 用户授权仅增加画面时, 禁止自动撰写新台词.
- 对确实影响音频或时长的歧义, 只询问一个最小必要问题.

### 5.2 产品文案约束

- 根据商品可信资料撰写新增台词, 不从未核实的素材文字推断功效.
- 对杀菌率, 成分, 认证和适用场景记录事实来源.
- 缺少依据时删除未授权断言, 或请求用户确认事实, 不让时长适配重试自动改变产品声明.
- TTS 文案改变后重新生成指纹, 配音与字幕时间必须重新匹配.

## 6. 目标执行流程

```text
读取冻结快照与用户要求
  -> 校验编辑意图, 时长与音频授权
  -> 复用可信素材分析并筛选候选
  -> 在候选素材内定位局部有效区间
  -> 按内容质量与展示完整性排序
  -> 仅在需要时生成局部配音
  -> 读取配音样本长度并计算整数帧预算
  -> 组合有效选段并匹配长度
  -> 自动修正可处理的轻微差异
  -> 编译完整轨道, 统一检查要求与内容边界
  -> 无阻塞时进入预览渲染
  -> 检查实际帧数, 音频样本, 字幕与完整解码
  -> 用户播放核对
  -> 用户接受后另存精修版本
```

每个阶段必须输出可追踪结果. 仅在非自动可修正的条件下停止, 不将正常配音准备或内部长度调整标记为用户缺少素材.

## 7. 精准素材选段

### 7.1 两层候选结构

将素材级召回和片段级选择分开:

1. 素材级召回: 复用现有分析, 找到同商品且与目标有关的素材.
2. 片段级定位: 在召回素材中找到目标内容的实际时间区间.

为每个局部候选保存:

| 字段 | 说明 |
| --- | --- |
| `candidate_id` | 当前分析版本下稳定的候选标识 |
| `asset_id` / `content_hash` | 素材归属与内容绑定 |
| `source_range` | 实际拟使用的局部时间区间 |
| `safe_range` | 已核验可裁切和适度延长的内容范围 |
| `preferred_range` | 优先保留的完整展示或动作核心 |
| `content_tags` | 包装展示, 抽取湿巾, 擦拭, 清洁效果等 |
| `product_match` | 商品与包装一致性依据, 未确认项 |
| `action_complete` | 是否覆盖目标动作, 以及证据 |
| `verification` | 核验方法, 采样时间, 风险和置信等级 |
| `rejection_reasons` | 字幕, 遮挡, 无关内容, 越界等拒绝原因 |
| `locator_version` | 定位算法, 模型与提示版本 |

`safe_range` 必须来自核验, 不能直接等于整个文件. 没有证据时保持范围未确认, 不允许自动向外延长.

### 7.2 定位步骤

1. 读取已有 `highlights`, 镜头说明和可信商品信息.
2. 对高相关候选抽样读取真实画面, 初步定位商品清楚出现的位置.
3. 在疑似镜头切换, 字幕变化和动作边界附近加密采样.
4. 对复杂动作使用短视频区间核验, 或逐步细化时间边界.
5. 区分完整展示动作和准备动作, 生成优先范围与可调整范围.
6. 检查时间戳, 商品, 字幕和素材归属后, 才将候选交给选段规划器.

- 优先复用已有分析, 只对进入短名单的局部执行新增核验.
- 已有分析缺少片段时, 将全素材仅作为待定位范围, 不直接作为可信展示片段.
- 外部模型只能返回当前素材中有依据的时间范围, 由后端检查所有坐标和引用.
- 对单帧商品特写与连续动作使用不同核验标准.
- 不对采样未覆盖的中间区间做绝对结论.

### 7.3 内容选择规则

按以下顺序做决策, 不允许高分抵消硬性违规:

1. 排除越界, 跨企业, 商品不符, 硬字幕冲突和来源失效的片段.
2. 优先选择目标内容和商品主体清楚可见的区间.
3. 优先保留动作核心, 不从擦拭中途开始或在清洁效果出现前结束.
4. 优先选择一个合适的连续镜头, 避免不必要的多片段拼接.
5. 必须组合时, 选择互补内容, 不重复使用重叠画面凑长度.
6. 在质量相近的候选中, 优先选择长度最接近目标且可安全微调的区间.

商品级相关性分数只用于召回与初步排序. 最终选择必须同时考虑局部质量, 动作完整性和长度可适配性.

### 7.4 从有效区间内部选点

- 商品特写: 从包装稳定, 对焦清晰的区间选择起点, 不固定从候选起点截取.
- 使用动作: 优先保留动作开始到目标结果出现的完整区间.
- 清洁效果: 保留用户能辨认效果的展示时长, 不只取最后一帧.
- 对质量一致的稳定镜头, 允许在 `safe_range` 内滑动窗口匹配目标长度.
- 对动作镜头, 仅调整可裁切的前后缓冲, 不切入动作核心.
- 如果目标时长无法覆盖动作核心, 换选更短的完整动作或请求调整目标, 不机械截断.

### 7.5 多片段组合

- 使用整数帧预算分配每个输出片段的长度.
- 约束最大选段数量, 防止出现大量碎片化镜头.
- 对同素材的重叠范围去重, 允许不重叠且内容互补的不同局部.
- 不默认跨越两个有效区间之间未经核验的空白.
- 保留整体目标帧数, 各片段只消费剩余帧预算, 最后一个选段不得额外向上取整.
- 以台词语义与展示内容对应为目标, 不仅以填满时长为目标.

## 8. 统一时间基准

### 8.1 权威坐标

- 输出视频: 使用整数帧边界和有理数帧率作为权威坐标.
- 独立配音: 使用解码后的样本数和采样率作为权威长度.
- 源素材: 使用经过校验的源时间戳或 PTS 范围, 不把输出帧索引当作源帧索引.
- 整数毫秒: 用于 UI 展示和旧协议适配, 不用于新协议反复计算总长度.
- 所有区间采用半开区间, 即包含开始, 不包含结束.

输出帧率必须读取媒体探测的有理数表示, 如 `30000/1001`, 不仅保存浮点 `29.97`. 浮点数可用于显示, 不作为精确预算依据.

### 8.2 配音到画面预算

设:

- 配音样本数为 `S`.
- 音频采样率为 `R`.
- 输出帧率为 `p/q`.

使用整数运算:

```text
ceil_div(a, b) = (a + b - 1) // b
required_frames = ceil_div(S * p, R * q)
video_duration_seconds = required_frames * q / p
```

- 所有素材片段的输出帧数之和必须等于 `required_frames` 或明确授权的展示停留目标.
- 不先将配音转换为整数毫秒, 再向上取整一次, 再逐片段向上取整.
- 不对每个片段分别向上取整音频样本数后累加.

### 8.3 全局边界与音频对齐

采用统一的全局边界转换规则:

```text
sample_at_frame(k) = ceil_div(k * R * q, p)
clip_samples = sample_at_frame(end_frame) - sample_at_frame(start_frame)
```

- 用同一全局边界计算相邻区间, 保证样本连续且不累计舍入.
- 根据片段实际开始帧计算 TTS 可容纳样本数, 不只比较四舍五入后的毫秒.
- 将未修改的原音轨映射到对应保留区间, 不通过尾部补静音掩盖缺失原台词.
- 字幕基于可信语音时间生成, 对齐到输出时间轴, 不延长字幕来掩盖音频不足.
- 最终封装存在音频编码器延迟或容器时间基差异时, 单独记录和验证, 不混入内容留白阈值.

### 8.4 不同帧率与可变帧率素材

- 统一输出到已确定的 CFR 帧率, 保持原片既有画幅策略.
- 源素材区间使用真实时间戳定位, 由解码和输出重采样产生所需输出帧数.
- 不假设输入素材与输出帧率相同.
- 对 VFR 素材记录时间戳来源和规范化策略, 不仅使用 `fps * duration` 猜测可用帧数.
- 渲染前确认有效源区间能解码出所需输出画面, 不能默认在尾部复制最后一帧补齐.
- 记录源区间到输出区间的映射, 保证素材来源可追溯.

### 8.5 案例期望

任务 21 的 `9240ms` 配音在 `30fps` 下需要 `278` 帧, 对应约 `9266.667ms`.

- 使用 `278` 帧作为预算, 不产生 `279` 帧的额外画面.
- 在旧毫秒协议中, 允许通过确定性的末段裁切达到一帧以内差值.
- 在新帧协议中, 验收总帧数与音频样本预算, 不要求每段显示毫秒差值的求和等于真实媒体时长.
- 最后一个素材若不能安全裁短, 应重新分配其他片段或更换候选, 不切断有效展示动作.

## 9. 时长适配与留白策略

### 9.1 区分三个概念

| 类型 | 含义 | 是否需要用户说明 |
| --- | --- | --- |
| 技术性帧尾留白 | 画面完整覆盖配音后, 不足一帧的自然尾差 | 不需要, 由系统记录 |
| 内容性展示停留 | 新增展示段明确保留短暂无讲话的画面 | 在授权策略范围内自动记录, 较长停留需明确意图 |
| 缺失音频 | 台词未生成完整, 音轨异常或原声丢失 | 不能当作留白放行 |

### 9.2 建议默认策略

| 场景 | 允许行为 | 禁止行为 |
| --- | --- | --- |
| 新增 TTS 商品展示段 | 先匹配帧预算, 正常技术尾差自动放行 | 截断配音或超范围延长素材 |
| 已授权的新增展示停留 | 最多 `100ms` 的内容性尾部静默, 作为本期初始策略 | 将 `100ms` 作为所有轨道的全局容差 |
| 替换原口播 | 在授权区间内适配, 仅接受技术尾差 | 默认延长区间或侵占下一句 |
| 仅替换画面 | 保留原配音, 精确覆盖既有输出区间 | 自动添加 TTS 或改变总时长 |
| 配音长于画面 | 在有效范围内延长或换选素材, 重新计算 | 以负向容差放行被截断台词 |
| 明确无讲话展示段 | 按用户意图安排画面, 无 TTS | 为该场景强制生成新口播 |

- `100ms` 是建议的初始内容策略, 不是经过线上质量实验验证的最佳值.
- 将其计入方案预计总时长, 不允许渲染阶段偷偷增加.
- 对低帧率视频, 技术尾差可能超过 `100ms`. 使用不足一帧的技术边界规则处理, 不把它误判为内容停留.
- 固定总时长, 字幕边界和下一句原声等约束优先于留白策略.
- 记录允许留白的场景, 实际长度和策略版本.

### 9.3 自动适配顺序

1. 重新按整数帧预算裁切, 消除计算误差.
2. 在当前有效范围内滑动或调整最后一个选段.
3. 在其他选段的可裁切缓冲中重新分配帧数.
4. 换用长度更合适且质量不降低的候选.
5. 必要时添加内容互补且经过核验的局部片段.
6. 对符合授权场景的小幅尾部静默, 按策略记录并放行.
7. 仍无法满足时, 输出具体原因和一个可执行操作.

不得自动通过大幅延长空镜, 静音填充缺失台词, 重复素材或改变台词内容来适配.

## 10. 有界自动修正

### 10.1 修正边界

- 只修正用户授权编辑项内部的选段与技术时间差.
- 不移动未经授权的源片插入位置, 不改动未关联的镜头或口播.
- 已确认方案的修正必须形成新修订, 旧确认与旧预览不能继续复用.
- 自动生成阶段的内部修正可以在同次作业中完成, 但必须写入最终结果与修正记录.
- 相同输入与相同策略重复编译, 必须产生相同选段和哈希.

### 10.2 重试分类

- 确定性时间修正: 本地执行, 不调用 LLM 或 TTS.
- 内容换选: 只核验尚未尝试的候选, 不重复评估相同失败片段.
- 服务重试: 处理网络和提供商临时异常, 不与内容修正次数混用.
- 用户修改: 根据改变的输入定向失效缓存, 不默认重跑全部流程.

建议初始限制:

- 每个编辑项最多进行 `2` 轮内容换选与修正.
- 当前任务单次分析最多定位 `6` 个高相关素材.
- 每个素材本轮最多细化 `3` 个候选范围.
- 每个编辑项优先使用 `1` 个片段, 初始组合上限为 `3` 个片段.
- 每次执行同时受总时长, 模型调用次数和预算上限约束.

以上为建议初始配置. 上线前以样本测试校准, 达到边界时说明原因, 不静默忽略用户要求.

### 10.3 修正记录

每次修正记录:

- `item_id`, 原始候选和原始选段.
- 修正前后的帧数, 样本数和展示毫秒.
- 修正类型, 触发错误码, 使用的策略版本.
- 素材有效范围与内容证据引用.
- 是否改变预计总时长, 是否需要重新确认.
- 尝试次数和最终结果.

修正日志只存必要结构化信息, 不写入签名链接, API Key 或原始媒体数据.

## 11. 协议, 数据与缓存设计

### 11.1 分阶段协议演进

短期修复继续使用 `video_refinement_plan.v2`, 仅修正已有字段计算与行为. 不将新结构直接塞入 `extra="forbid"` 的编辑项请求.

完整帧协议采用新的 `video_refinement_plan.v3` 和相应快照版本, 明确增加以下权威数据:

- 有理数输出帧率.
- 输出轨道的整数帧边界.
- 配音解码样本数与采样率.
- 局部候选证据与允许调整范围.
- 音画适配策略和自动修正记录.
- 编译器, 定位器与渲染器版本.

必须显式修改 `compile_plan` 与渲染派发. 当前实现对非 v2 快照会进入旧逻辑, 不能只增加版本字符串而不新增分支.

### 11.2 建议数据结构

以下为 v3 方案局部示意, 不是完整 API 请求:

```json
{
  "schema_version": "video_refinement_plan.v3",
  "timing": {
    "fps_num": 30,
    "fps_den": 1,
    "sample_rate": 48000,
    "compiler_version": "frame-budget-v1"
  },
  "item_timing": {
    "item-insert-001": {
      "voiceover_sample_count": 443520,
      "target_frame_count": 278,
      "actual_frame_count": 278,
      "padding_policy": "technical_frame_tail",
      "padding_samples": 1280
    }
  },
  "automatic_adjustments": [
    {
      "item_id": "item-insert-001",
      "type": "trim_last_segment",
      "reason_code": "FRAME_BUDGET_CORRECTION",
      "before_frame_count": 279,
      "after_frame_count": 278
    }
  ]
}
```

帧边界归属于输出时间轴, 源素材区间仍保留独立时间戳. `padding_samples` 必须与编译后的实际片段全局边界核对, 示例不能代替运行时计算.

### 11.3 留白字段

- 短期兼容原 `narration_padding_reason`, 但不依赖自由文本判断是否安全.
- 新协议采用结构化 `padding_policy`, 实际样本差和授权依据.
- 编译器, 渲染器和任务序列化使用同一策略函数.
- 旧版本收到新增字段时应明确拒绝或要求升级, 不静默忽略.
- 系统技术留白记录与用户主动要求的停留说明分开保存.

### 11.4 缓存失效

候选定位缓存键至少包含:

- 企业, 商品和素材内容哈希.
- 目标内容与可信商品信息摘要哈希.
- 输入分析版本, 定位算法版本, 模型与提示版本.
- 采样或短视频核验方式及参数.

时间编译与预览指纹至少包含:

- 冻结快照, 素材选段和用户要求.
- 配音内容指纹与真实样本元数据.
- 有理数输出帧率, 时间编译版本和留白策略.
- 最终修正后的轨道与渲染器版本.

不要将整个缓存键仅绑定到素材 ID. 内容, 策略或编译器改变后必须定向失效, 但允许复用未变化的 TTS 和可信素材分析.

### 11.5 持久化与来源映射

- 优先利用现有分析结果, 方案 JSON 和预览校验 JSON 保存新增数据.
- 若增加配音样本字段或独立候选表, 提供显式, 可回退的数据库迁移与字段默认值.
- 不将初始化脚本当作隐式线上数据修复工具.
- 精修版本记录实际使用的局部源区间, 不只记录素材 ID.
- 新协议的来源映射由权威轨道生成, 不从 UI 毫秒文本反推.

## 12. 状态, 错误与界面行为

### 12.1 阻塞分类

将内容问题, 输入问题, 技术问题和服务问题分开. 以下为建议分类:

| 分类 | 示例错误码 | 系统行为 | 用户操作 |
| --- | --- | --- | --- |
| 技术时间差 | `FRAME_BUDGET_MISMATCH` | 自动重算并修正 | 无 |
| 可调整选段 | `SEGMENT_FIT_REQUIRED` | 在有效范围内调整或换选 | 自动修正失败后再提示 |
| 可接受展示停留 | `DISPLAY_TAIL_PADDING` | 记录为非阻塞提示 | 播放核对 |
| 配音超过授权区间 | `VOICEOVER_TOO_LONG` | 尝试安全适配, 不截断 | 改短台词或授权增加时长 |
| 素材不足 | `MATERIAL_COVERAGE_INSUFFICIENT` | 停止无效换选 | 补充指定类型素材 |
| 内容核验不足 | `CONTENT_REVIEW_REQUIRED` | 不声明素材绝对可靠 | 核对片段或换选 |
| 需求冲突 | `REQUIREMENT_CONFLICT` | 保留冲突证据 | 调整目标或优先级 |
| 音频服务失败 | `VOICEOVER_PROVIDER_FAILED` | 有界服务重试 | 检查配置或重试 |
| 渲染失败 | `RENDER_VALIDATION_FAILED` | 保留可复用结果, 分类重试 | 查看具体失败阶段 |

在短期版本中, 可保留现有错误码并增加分类映射. 新错误码启用时必须同步更新前端, 测试和监控.

### 12.2 要求状态

- 只有真正缺少可用素材时才标记 `AWAITING_MATERIAL`.
- 只有缺少用户输入时才标记 `NEEDS_CLARIFICATION`.
- 可自动修正的技术差异不应改变要求的规划可执行状态.
- 内容核验或渲染问题单独记录执行阻塞, 不假装用户需要补素材.
- 若增加新的要求状态枚举, 必须同步 API 和前端兼容; 本期可优先采用原要求状态加独立阻塞分类.
- 避免把根因错误和泛化的关联错误重复显示为两个独立问题.

### 12.3 进度展示

以真实阶段更新进度, 不使用无法依据工作量推导的百分比:

- 正在解析精修目标.
- 正在匹配相关素材.
- 正在定位商品展示片段.
- 正在生成局部配音.
- 正在匹配音画时长.
- 正在自动调整选段.
- 正在生成完整预览.
- 预览已生成, 请播放核对.

计数同时显示已匹配素材, 已核验片段和实际使用片段. 不把所有已评估素材都表述为已经完整观看.

### 12.4 素材使用信息

对每个使用片段展示:

- 素材名称和来源 ID.
- 实际使用的源素材起止时间.
- 使用长度和对应目标内容.
- 选择理由与核验方法.
- 自动调整前后的差异.
- 商品与字幕等尚未确认的风险.

提供选段播放和修改前后连续预览. 如增加人工调节范围, 必须显示安全边界, 保存后重新编译, 失效旧确认与旧预览.

### 12.5 提示示例

非阻塞提示:

```text
已自动缩短最后一个商品展示片段一帧, 配音完整保留.
```

真实素材不足:

```text
新增讲解需要约 9.27 秒画面, 当前已核验的有效选段只有 6.10 秒.
请补充同商品的无字幕包装展示或使用演示素材.
```

配音超出固定区间:

```text
新配音长于允许替换的原句区间, 无法在不截断台词的情况下完成.
请精简台词, 或明确允许增加视频时长.
```

已取消任务:

```text
该任务已取消, 不再继续处理. 可以沿用精修目标新建任务.
```

## 13. 并发, 重试与任务安全

- 沿用现有修订号和条件更新, 所有结果发布前核对任务状态与作业修订.
- 自动修正和渲染之间再次确认来源哈希和最终方案哈希.
- 在新增定位和修正的长耗时阶段检查取消与 superseded 状态.
- 不在进行外部模型请求期间长期持有数据库事务或锁.
- 重试复用同指纹的成功 TTS, 避免重复计费与重复配音.
- 同一个任务的同一修订只发布一个有效分析结果和预览.
- 服务重启后恢复作业时重新校验版本和阶段, 不默认发布过期中间结果.
- 自动修正记录属于最终方案的一部分, 确认后不得就地修改而保持原哈希.
- 限制模型输出数量, 时间范围和字段长度, 校验数据后再调用媒体工具.
- 使用固定媒体命令参数与受控路径, 不把模型文本拼成 shell 命令.

### 15.2 API 和状态测试

- 正常技术差异不返回需要用户补素材的状态.

## 16. 验收标准与指标

### 16.1 功能验收

- 任务 21 等价输入在隔离环境中能够自动完成时间适配并生成可解码预览.
- 不要求用户处理该案例的 `59ms` 计算差异.
- 画面总帧数与确认方案一致, 配音有效样本不被截断.
- 商品出现在素材中部时, 能选择有证据的中部区间.
- 使用多个片段时, 每个片段都有实际源时间, 内容依据和来源映射.
- 未经授权不增加台词, 不延长原片, 不使用其他商品素材.
- 自动修正不能突破有效范围或改变动作核心.
- 超出可修正范围时, 显示根因与必要操作, 不泛化为素材缺失.
- 取消与修订并发测试通过, 历史方案可读取.

### 16.2 上线观察指标

| 指标 | 定义 |
| --- | --- |
| 技术差异阻塞率 | 因可修正帧取整问题停止的任务 / 进入适配阶段的任务 |
| 首次预览成功率 | 无用户重新提交即生成预览的任务 / 有授权且素材充足的任务 |
| 自动修正成功率 | 修正后通过编译和渲染的任务 / 尝试自动修正的任务 |
| 素材局部有效率 | 人工核对通过的使用片段 / 抽查片段 |
| 口播完整率 | 尾部有效语音与样本完整保留的检查结果 |
| 误报缺素材率 | 被标缺素材但实际属于时间或服务问题的任务比例 |
| 无授权新增台词数 | 仅增加画面目标却新增台词的任务数 |
| 成本与延迟 | 单任务定位调用数, TTS 次数, P50/P95 耗时和费用 |

确定性回归集的技术差异阻塞和未经授权修改应为 `0`. 线上成功率与性能改善目标必须先采集基线再确定, 不预设没有测量依据的提升比例.

内容质量由人工抽查与真实预览验收评估, 不以媒体解码成功替代.

## 18. 灰度, 回退与历史任务

### 18.1 建议灰度开关

新增配置的具体名称由实施时确定, 但必须能够分别控制:

- 新时间编译协议.
- 局部素材定位.
- 自动内容换选与修正.
- 新增展示段内容性停留策略.

关闭定位能力不代表可以直接将整个素材视为已核验. 应使用原有可信候选或明确说明核验不足.

### 18.2 部署顺序

1. 部署能读取旧方案和新方案的服务, 暂不生成新协议.
2. 完成迁移, 前端字段兼容和所有 worker 能力检查.
3. 在隔离环境完成回归和真实媒体验收.
4. 启用少量新任务, 确认失败分类和费用信息.
5. 逐步扩大灰度, 持续抽查内容质量.

### 18.3 回退规则

- 优先关闭新任务生成开关, 保留能够读取已经创建的新方案的服务.
- 旧镜像不支持 v3 时, 禁止让它接管 v3 作业.
- 已创建 v3 作业由支持版本处理或明确暂停, 不静默降级成 v1/v2.
- 不回写已确认方案, 不删除已接受版本.
- 保留新协议来源映射和审计记录, 不为回退破坏历史数据.

### 18.4 任务 21 与其他历史任务

- 任务 21 已取消, 不自动恢复或修改其状态.
- 如需验证相同目标, 使用经授权的新任务和可复用来源, 保存独立修订记录.
- 对尚未取消且只因技术误差阻塞的任务, 提供重新计算入口, 产生新修订.
- 来源或策略变化后重新校验, 不直接复用旧确认哈希.
- 不通过批量 SQL 修改历史方案的片段时长来代替编译器修复.

## 19. 风险与控制措施

| 风险 | 控制措施 |
| --- | --- |
| 只放宽编译校验, 渲染仍失败 | 共享帧预算, 样本边界和留白判定函数 |
| 秒数正确但视频帧数不正确 | 验证实际帧数, 不仅检查容器 duration |
| 微调选段破坏完整动作 | 保护动作核心, 仅使用已核验缓冲范围 |
| 少量采样漏掉字幕或商品切换 | 在变化区间加密采样或短视频核验, 保留置信边界 |
| 新增定位导致费用或延迟失控 | 复用分析, 短名单定位, 总调用与时间预算 |
| 自动修正改变用户意图 | 明确音频授权, 限制编辑范围, 修订和审计 |
| TTS 重试产生重复收费 | 内容指纹复用, 区分服务重试与选段修正 |
| 新旧缓存混用 | 算法, 协议和策略版本进入缓存指纹 |
| 取消或新修订后发布旧结果 | 发布前条件更新, 长阶段取消检查 |
| 同商品标签但实际包装不符 | 视觉证据核验, 未确认时不宣称 SKU 已验证 |
| 内容性停留掩盖音频缺失 | 基于真实样本与完整台词, 限定新增展示场景 |
| 新方案被旧 worker 错误处理 | 显式版本派发与能力隔离, 分阶段部署 |
