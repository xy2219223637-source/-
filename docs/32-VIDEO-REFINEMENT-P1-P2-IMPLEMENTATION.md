## 1. 编辑项授权

- 使用 `refinement-authorization-v1` 从用户原文原子分句和对应要求的人工回答确定权限.
- 保存 `request_quote` 并校验它对应用户原文, 不信任模型返回的权限标志或自动预览选项.
- 禁止将一个要求的配音授权扩散到另一个画面要求, 禁止把多个不同意图的要求合并为更宽权限.
- 只增加画面默认覆盖现有区间, 保留原配音和时长; 明确插入无讲话展示时不生成 TTS.
- 人工保存仅为实际改动的字段增加对应编辑项权限. 未改动的其他项不会因保存整份草稿获得配音授权.
- 缺少授权时保存 `EDIT_AUTHORIZATION_REQUIRED` 根因, 对应要求进入 `NEEDS_CLARIFICATION`, 不先生成收费 TTS.
- 重复验证重建派生阻塞, 不重复追加同一条泛化错误.

## 2. 精确时间协议

| 项目 | 实现 |
| --- | --- |
| 方案版本 | `video_refinement_plan.v3` |
| 时间编译版本 | `v3-frame-sample-1` |
| 渲染器版本 | `v3-render-1` |
| 输出权威坐标 | `output_frames.start_frame/end_frame`, 有理数 `summary.frame_rate` |
| 音频权威坐标 | `output_samples.start_sample/end_sample`, 48kHz 全局样本边界 |
| 原片画面坐标 | `source_normalized_frames`, 明确表示 CFR 规范化后的坐标, 不是输入素材帧索引 |
| 素材来源 | 保留真实 `source_range` 时间范围和内容哈希, 不将输出长度当作来源长度 |
| 配音长度 | 标准 WAV 中的真实 `timing.audio.sample_count/sample_rate/channels/format` |

- 编译共享既有编辑语义校验器, 在 v3 模式下内部统一使用整数帧, 仅在序列化 UI 时转换毫秒.
- 按实际输出开始帧计算 TTS 最小预算, 不逐段取整音频长度.
- ffprobe 提供有理数帧率和视频 PTS 时长. 缺少流时长时读取包 PTS 和包持续时间, 不从显示浮点帧率反推精确率.
- 原音轨按可信样本边界截取; 原音轨偏移不为零或有效长度超出视频预算时明确阻塞, 不偷偷改变同步或截断台词.
- 缺少原音轨有效时长时明确阻塞. 本轮没有实现混合音轨分离或任意非零音轨偏移的自动修复.
- 新 TTS 不按毫秒 `atrim`, 实测样本数必须等于绑定资产元数据. 超出输出一个样本也不截断.
- 分别检查每个画面段和最终视频的完整解码帧数, 不通过循环或 `tpad` 复制末帧补足.
- 素材在重置 PTS 前按源时间范围裁切, 防止 seek 后晚到的第一帧被伪装成范围内画面.
- 原字幕和 TTS 字幕保留可信样本时间, 不将台词时间反复量化为帧后再转回毫秒. ASS 的最终显示仍受其原生厘秒分辨率限制.
- 接受版本时使用权威输出帧边界和真实来源结束时间, 不用容器时长覆盖最后一个来源区间.
- 旧 v1/v2 保持读取与渲染兼容; 未知版本和不支持的 v3 时间/渲染版本明确拒绝.

## 3. 局部选段

- 区分素材召回和局部定位. 缺少 highlights 的全素材候选仅标记为待定位, 不自动作为可信安全范围.
- 每个编辑项最多定位 6 个素材, 每素材最多 3 个候选范围; 每次准备阶段最多 12 次定位模型调用, 最多使用 3 个选段.
- 第一轮在候选中采样 9 个时间点. 第二轮对返回的安全边界和动作核心加密采样, 不宣称连续观看.
- 要求商品画面依据, 明确的叠加字幕判断和完整动作核心. 包装印刷文字不作为叠加字幕.
- 保存内容哈希, `candidate_id`, `safe_range`, `preferred_range`, 商品依据, 核验时间点, 风险和 `sampled-local-v1` 版本.
- 稳定特写从有效区间内部选择窗口; 动作镜头必须包含完整核心, 不能通过机械截短动作填满预算.
- 对同素材的重叠使用去重, 不跨安全区间补长, 不循环重复片段.
- 编译再次检查核验记录与当前素材哈希, 实际源区间和动作核心. 缺少依据时返回 `CONTENT_REVIEW_REQUIRED`.
- 缓存包含企业, 商品, 素材哈希, 目标, 商品资料, 分析结果, 模型, 采样参数和定位版本.
- 完成的局部核验按检查点保存至作业批次 JSON, 同修订重试可复用; 每个长阶段和发布前重新检查取消与修订.
- 页面显示实际渲染使用区间, 选择理由, 采样范围和 SKU 尚需人工核对, 不把采样成功当作内容已经人工验收.

## 4. 留白与指标

- 技术性尾差使用严格不足一帧的样本规则; 旧 v2 保留明确的毫秒适配误差边界.
- 只有启用场景策略且授权了新增商品展示的插入项, 才能允许至多 100ms 内容性尾部停留.
- `narration_padding_reason` 文本不再能为新生成方案绕过有界留白校验. 替换口播不使用展示段的 100ms 容差.
- 在方案 JSON 保存实际分析调用数, 定位调用与缓存命中数, TTS 生成/复用次数, 使用选段数, 自动修正次数和阶段耗时.
- 预览校验保存实测帧数, PCM 样本数, 有理数输出帧率和容器时长差.
- 本轮未采集线上成功率基线, 未估算未经测量的费用或收益. 人工内容有效率和费用归因仍需灰度样本建立.

## 5. 灰度与 worker 隔离

全部新功能开关默认关闭, 企业白名单默认空. 设置白名单且启用对应开关后, 只影响新生成方案.

```text
REFINEMENT_PRECISE_TIMING_ENABLED=false
REFINEMENT_LOCALIZATION_ENABLED=false
REFINEMENT_CONTENT_RESELECTION_ENABLED=false
REFINEMENT_DISPLAY_TAIL_ENABLED=false
REFINEMENT_ROLLOUT_TENANTS=
```

- 精确协议必须能运行 ffprobe. 设置 `DIRECTOR_FFPROBE_PATH`, 或将 ffprobe 放入 PATH 或实际 FFmpeg 相邻目录.
- 本机当前已确认有 FFmpeg, 尚未找到 ffprobe. 本轮真实渲染测试使用测试生成器提供的可信有理数/PTS 元数据; ffprobe JSON 解析使用进程桩测试. 未修改本机媒体工具或生产 `.env`.
- 新分析, 配音和预览使用 `queued_v3` 运输状态; 处理中分别使用 `analyzing_v3`, `generating_v3`, `rendering_v3`.
- 此后缀表示当前 worker 协议, 不表示所有任务都采用 v3 时间方案. 默认 v2 的新任务也要求具备独立授权保护的当前 worker.
- 只查询旧 `queued` 的 worker 不会认领新任务; 旧启动恢复逻辑也不会将这些处理中状态改回旧队列.
- API 将运输状态映射为既有 `queued/analyzing/generating/rendering`, 前端不需要引入不兼容状态.
- 当前 worker 继续处理旧队列. 重启恢复保留新运输状态, 不将 v3 作业降为旧队列.
- 已创建 v3 作业重试和已有 v3 方案保存/重新分析, 即使关闭生成开关也保留 v3, 不静默降级.
- 部署时先更新 API 与 worker, 验证所有新状态可认领, 再启用白名单. 回退时关闭新功能生成开关, 保留支持新运输/时间协议的 worker 处理已创建任务; 不使用旧镜像强行认领.

## 8. 本地排队不执行修复

- 根因: 本地 `RUN_BACKGROUND_WORKERS=false`, API 仍允许创建异步精修作业, 页面把排队显示为正在准备方案. 任务 22 的分析作业为 `queued_v3`, 执行次数为 0, 没有开始时间.
- 新增可选 `RUN_REFINEMENT_WORKER`. 未设置时继承 `RUN_BACKGROUND_WORKERS`; 显式设置可只启用精修或单独关闭精修, 不改变其他业务队列.
- 本地使用 `RUN_BACKGROUND_WORKERS=false` 与 `RUN_REFINEMENT_WORKER=true`. 保持数据库初始化, 通用启动恢复及 P1/P2 灰度开关的既有设置.
- `/api/health` 和精修任务响应提供精修 worker 的 `running/disabled/stopped` 状态. 检查真实线程存活状态, 不仅检查配置.
- worker 不可用时, 新建或重试分析, 配音与预览返回 503 和明确的服务提示, 不写入新的待执行作业. 既有排队记录保留, 已就绪结果仍可读取.
- 分析响应提供入队时间, 开始时间和等待秒数. 页面区分排队与执行, 长时间排队显示等待时间, 后台关闭或停止时不显示分析中的旋转图标.
- 页面轮询同步 worker 状态, 服务恢复后自动更新既有任务, 不要求用户重复提交.
- 隔离测试覆盖独立启动, 配置继承, 线程停止, 不可用时拒绝作业, 既有队列不被改写, 前端等待提示和服务恢复. 最后新增的启动日志另跑 3 项 worker 回归通过.
- 本地运行验证: `/api/health` 返回精修 worker `running`. 任务 22 被正常认领并复用 36 个素材的分析结果, 素材评估全部完成; 在方案生成阶段返回 `AI 未返回有效精修草稿`, 作业为 `failed`, 不再无限排队. 素材评估检查点保留, 未生成或接受精修预览. worker 排队修复不代表模型草稿返回问题已经解决, 后者仍需独立诊断.
