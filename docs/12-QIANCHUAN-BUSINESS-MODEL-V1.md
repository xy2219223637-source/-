# 千川业务形态 V1（讨论稿）

日期：2026-09-22。目标是保持现有成片页的报表字段与响应结构，同时把千川账户、推送与报表改为个人归属。本文是**目标设计，不是已上线能力**；具体接口传参和回参见 [10-QIANCHUAN-PERSONAL-ACCOUNT-ARCHITECTURE-AND-API.md](10-QIANCHUAN-PERSONAL-ACCOUNT-ARCHITECTURE-AND-API.md)。

## 一句话原则

**成片属于企业内容空间；千川授权、上传行为和可见投放数据属于授权人。**企业 owner 可以管理成片，不因此获得成员的千川令牌、账户或投放数据。

## 角色与归属

| 对象 | 归属/可见性 | 可执行操作 |
| --- | --- | --- |
| 成片及本地分类标签 | 沿用企业内容权限 | 原有查看、编辑、下载规则不变 |
| 千川授权连接 | 发起 OAuth 的登录用户 | 本人同步、重新授权、停用、解绑；管理员无隐式代管权 |
| 广告账号绑定 | 本人授权连接下发现的账号 | 本人选择目标账号并推送；账号 ID 不能作为越权查询凭证 |
| 上传任务、素材 ID、上传历史 | 本人连接 + 成片 | 本人查看、核验、重试；企业内其他人不可见 |
| 素材报表及缓存 | 本人连接 + 广告账号 + 素材 + 时间窗 | 只有通过本人权限校验后可拉取/读取；共享账号的上游汇总另按下文限制 |

同一个千川广告账号可能被多个真实用户授权，因此“广告账号 ID 相同”不代表本项目中的同一授权主体。建议同一用户对同一广告账号只保留一个有效绑定，重复授权更新本人连接；跨用户不合并连接、任务或缓存。

## 用户流程

1. 所有具有成片访问权的用户都能看到“绑定千川”入口。用户发起 OAuth，只为自己创建连接；授权成功后只列出自己可操作的账号。没有绑定时也能看到入口。
2. 用户在成片上点击“推送到千川”，选择自己的有效账号并提交。后台核验成片权限、连接归属、账号有效性；上传成功保存素材 ID/视频 ID。这一步只表示素材入库，**不是已投流**。
3. 成片详情的“投放分析”集中显示本人上传过的账号下拉框、该账号的推送状态、素材 ID、上传记录和素材报表。切换账号时这些内容一起切换。页面显示字段维持现状；接口返回的数据集改为只含本人记录。
4. 报表按本人账号 + 素材 ID + 时间窗按需查询。`no_data` 表示该时间窗没有匹配报表，不等于永久未投放。逐秒分析在权限与真实非空数据确认前保持不可用，不用固定时长播放率拼成逐秒曲线。
5. 本人可停用、重新授权或解绑。停用立即禁止后续平台调用并使待执行任务失效；重新授权刷新本人凭证；解绑是**本地移除**，不宣称千川平台侧已撤销授权。历史记录留存策略需另行确认。

## “不能看到别人投的数据”的严格边界

权限有两层，不能混为一谈：

- **本项目数据隔离**：所有连接、绑定、上传列表、上传详情、报表请求和缓存读取在后端验证 `tenant_id + owner_user_id + connection_id/binding_id`。他人的 ID 直接请求也返回 404。前端筛选不能代替这层控制。
- **上游统计归属**：千川若只返回“广告账号 + 素材”的汇总，同一素材被别人的计划复投时，返回值可能混入别人的消耗和成交。个人绑定本身不能拆分这些统计。若产品承诺“只看我投的”，必须有可验证的计划/广告归属和相应可筛选报表接口；**在此以前，无法证明归属的共享汇总不应标成‘我的投放数据’，严格模式下应隐藏该汇总**。

建议 V1 先完成本项目权限隔离及上传状态；素材报表只在能够证明其统计归属时展示为个人投放数据。若仍展示无法拆分的账号级素材汇总，必须明确标注“该账号该素材的汇总，可能包含其他人投放”，且这不满足用户提出的严格隐私目标。

## 页面与服务分工

| 位置 | 目标展示/行为 | 数据来源 |
| --- | --- | --- |
| 成片详情顶部 | 下载、推送入口；不显示账号或状态 | 本地成片 |
| 推送弹窗 | 绑定千川、本人连接管理、选择本人账号、提交推送 | 本人 `/accounts` 与 `/uploads` |
| 投放分析标签 | 本人账号下拉框、当前账号推送状态、素材 ID、上传历史、报表 | 本人上传记录 + 经权限校验的报表 |
| 分类与标签 | 与千川权限解耦 | 项目本地分类服务 |

当前已完成“投放分析”前端布局和按返回账号切换；**后端返回仍是企业范围**，不能因此认定账号隔离已完成。当前“绑定千川”按钮也仍受企业 owner 条件控制。

## 落地顺序与验收

1. 数据模型及迁移：明确连接的不可变 `owner_user_id`；绑定、上传、缓存通过连接追溯归属；旧记录能追溯才归属，无法追溯先隔离。个人级幂等键不得复用其他人的上传任务。
2. 后端权限：账户列表、OAuth 会话、同步、停用、解绑、上传、重试、报表、缓存和异步任务统一校验本人归属与连接状态；停用/解绑后令牌和旧任务不可继续使用。
3. 前端接入：绑定入口对所有合格用户可见，管理按钮只操作本人连接；投放分析沿用现有字段，但只消费后端已过滤的本人数据。
4. 数据口径：用确有投放的真实账号验证报表非空值、金额/比率单位、时间窗与归因；逐秒接口单独验证，失败继续显示不可用。
5. 双用户验收：同一企业 A/B 分别绑定，同一成片和同一广告账号场景下，列表、直接访问 UUID、缓存、重试均不可跨人；共享素材复投时不能把混合汇总说成 A 的数据。

## 需业务拍板的四项

1. 是否允许多人在本项目内授权同一个广告账号？若允许，无法按人拆分的素材汇总是隐藏，还是以“账号级汇总”警示展示？严格隐私目标建议隐藏。
2. “已投流”的定义：有匹配报表行、消耗大于零，还是计划状态为投放中？建议不要用“上传成功”推断。
3. 解绑后本人是否还能看历史上传与报表缓存？建议保留审计记录，但停止实时拉取；展示范围由留存政策确定。
4. 离职或账号交接如何处理？建议单独设计授权移交/审计流程，不能由企业 owner 默认读取个人令牌和历史。
