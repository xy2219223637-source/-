# 千川 Phase 5：单视频一键投流 Mock 演示

## Task

### Goal

只验证一条最小产品链路：用户确认一个成片及必要计划参数后，点击一次“创建并投流”，页面自动演示：上传素材 → 创建商品全域计划 → 平台审核 → 启用投放 → 投放中。

本阶段追求的是“一条视频能从上传走到投流”的产品演示，不追求覆盖千川全部投放形态和配置细节。

### Context

- 当前系统已有账号授权、账号同步、成片上传、素材核验和素材报表。
- 当前页面存在一条真实上传成功素材，可复用其账号、文件名与素材 ID 作为演示上下文。
- 后端已有独立计划表、本地草稿和 operation 保护代码，但真实提交路由、worker、平台审核回查与平台写入仍关闭。
- 原 Mock 页面要求逐个点击草稿、提交、审核、启用，偏开发测试，不适合产品演示。

### Scope

包含：

- 单个成片、单个广告账号、单个抖音号、单个商品、单条新商品全域计划。
- 最小计划参数：计划名称、日预算、目标 ROI。
- 一个主操作按钮“创建并投流”。
- 创建配置放在“推送投流”弹窗，不常驻占用投放分析页面。
- 自动展示五步进度：上传素材、创建计划、平台审核、启用投放、投放中。
- 展示 Mock 计划 ID、自动执行记录和固定演示指标。
- 创建完成后回传当前页面，在投放分析区常驻展示 Mock 计划筛选、状态和计划口径演示数据。
- 平台目录失败时，允许用户显式切换到 Mock 抖音号与商品目录。
- 支持中途取消并重置，完成后支持重新演示。

不包含：

- 添加视频到已有计划。
- 多视频、多计划、单创意/多创意分配和批量任务。
- 直播全域、直播乘方、商品乘方及其他广告目标。
- 定时创建、原片/转码、计划模板、素材淘汰和动态命名。
- 真实平台创建、审核、启用、数据库持久化、worker 和真实报表。
- 本阶段之外的安全性扩展。

### Interfaces

- 页面入口：成片详情顶部“推送投流”；投放分析区“创建新计划”。
- 创建组件：`QianchuanPlanModal -> QianchuanPlanCatalog -> QianchuanPlanDemo`。
- 查询组件：`QianchuanAnalysis -> QianchuanPlanDataPanel`。
- 输入：当前账号、抖音号、商品和具有 `material_id` 的成功上传记录。
- 上传记录匹配：优先使用相同 `binding_id`；兼容历史记录时使用相同 `advertiser_id`。
- 用户输入：`name`、`budget`、`roiGoal`。
- 主操作：`创建并投流`。
- 浏览器状态：`ready -> uploading -> material_ready -> creating -> reviewing -> approved -> enabling -> enabled`。
- 开关：开发环境默认开放；非开发环境仅在 `VITE_QIANCHUAN_PLAN_DEMO_ENABLED=true` 时开放。
- 输出：仅 React 浏览器状态，不调用上传或计划写 API，不写数据库。
- 页面内计划状态由 `FinalVideoDetail` 暂存；关闭弹窗后仍可筛选，刷新页面后重置。

### Constraints

- 页面必须持续显示 `DEMO / 非真实投放`。
- 页面必须说明不会重复上传或写入千川。
- 固定指标必须显示 `固定演示数据 · 非千川返回`。
- 用户只点击一次主按钮；上传、创建、审核和启用由演示状态机自动推进。
- 目录降级必须由用户显式触发，不得把 Mock 目录伪装为平台数据。
- `QIANCHUAN_PLAN_WRITE_ENABLED=false` 与 `QIANCHUAN_PLAN_WORKER_ENABLED=false` 保持不变。
- 不删除或绕过已有归属、幂等、CAS 和结果不确定保护代码。
- 该演示不证明真实平台写入、审核或投流能力已经可用。

### Tests

- 只读计划总开关关闭时，不展示旁路组件。
- 无本人账号时显示可行动提示。
- 真实目录可选择账号、抖音号和商品。
- 平台目录失败时可显式进入 Mock 目录。
- 历史上传 `binding_id` 口径不一致时，可按 `advertiser_id` 复用成功素材。
- 点击一次“创建并投流”后，状态自动从素材上传推进到投放中。
- 完成后显示 Mock 计划 ID、执行记录、固定指标和重新演示入口。
- 创建表单不在投放分析页常驻；关闭弹窗后，计划出现在常驻计划下拉框中。
- 无计划时展示空状态和“创建新计划”入口；多条 Mock 计划可切换。
- TypeScript 检查、全量前端测试和 Vite 生产构建通过。
- 浏览器人工验证五步进度及一键自动推进。

### Definition of Done

- [x] 产品范围收缩为单视频、单新计划、商品全域成功路径。
- [x] 多个开发测试按钮合并为“创建并投流”。
- [x] 五步进度条覆盖上传、建计划、审核、启用和投放中。
- [x] 自动执行期间不要求用户继续点击。
- [x] 创建能力已移动到弹窗，投放分析页只常驻计划筛选和计划数据。
- [x] 弹窗完成结果可以回传当前页面并加入 Mock 计划下拉框。
- [x] Mock 与真实能力边界有明确文案。
- [x] 没有调用真实上传或计划写接口，没有数据库写入，没有启动 worker。
- [x] 自动化测试（15 项）、类型检查和生产构建通过（2026-09-24）。
- [ ] 浏览器现场点击验收（本轮浏览器自动化连接不可用，待恢复后补验）。

## 后续真实接入映射

产品上仍保持一次点击，但真实执行不能是一个同步请求：

1. 上传服务返回并核验 `material_id`。
2. 计划服务创建本地草稿并提交创建 operation。
3. 独立 worker 创建平台计划并回查平台计划 ID。
4. 审核中状态必须等待平台回调或轮询，不得本地直接改为通过。
5. 审核通过后再由独立 operation 启用投放。
6. 前端持续读取同一个流程实例的当前步骤。

因此，一键是用户体验层的编排，不表示真实平台调用可以被压缩成一个不可恢复的同步事务。
